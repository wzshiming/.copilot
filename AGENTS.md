# AGENTS.md

Personal agents repository, cloned as `~/.claude` — Claude Code agent definitions, the scripts they run, and the adapter that generates their VS Code Copilot copies; no application code.

## Structure

Only `.github/`, `agents/`, `copilot/`, `scripts/`, `tests/`, the dotfiles `.gitignore` lists, `AGENTS.md`, `README.md`, `LICENSE`, and `Makefile` are tracked; everything else at the root is Claude Code's own runtime state excluded by the `.gitignore` whitelist.

### Scripts

- Each script lives in `scripts/<name>.sh` as POSIX sh (`#!/bin/sh`, clean under `shellcheck -s sh`), called as `~/.claude/scripts/<name>.sh [-C <repo-path>] <args>`; the lock block `take_lock` is identical in `scripts/worktree-add.sh` and `scripts/worktree-remove.sh` and is edited in both together.
- A script never prompts, reads no environment variable as configuration, and never forces; an unmet precondition makes it refuse and say why.
- Exit codes: `0` done, `1` refused or failed, `2` usage error; a script's `--help` may define more (`ci-wait.sh`: `3` still pending at the deadline); results print as `key=value` lines, a listing (`worktree-status.sh`) as one line per item, a watcher as one progress line per poll plus the final table; `--help` prints one paragraph.
- Tests live in `tests/<name>.bats` (bats-core); reusable fake commands live in `tests/mock/<cmd>`, clean under `shellcheck -s sh`, never as stubs written inside a single `.bats` file.

### Agents

- Each agent lives in `agents/<name>.md`, the Claude Code format and the only source: frontmatter `name`, `description`, `tools` (Claude Code tool names, `Agent(<names>)` listing the dispatchable subagents), and `model` (an alias: `haiku`, `sonnet`, `opus`, `fable`); the body never carries Copilot wording.
- The description ends with `Brief:` and what a dispatch must carry — Claude Code shows a dispatcher nothing else of the target; `scripts/copilot-install.sh` splits it off as the Copilot `argument-hint`.
- Copilot copies are generated, never tracked: `scripts/copilot-install.sh` writes `~/.copilot/agents/<name>.agent.md` from the source's name and description, `copilot/<name>.yml` (the remaining Copilot frontmatter: `model` fallback list, `tools`, `agents`, and where applicable `user-invocable`, `disable-model-invocation`, `handoffs`), and the body with each `<`/`>` pair of `copilot/map` replaced literally; a body edit touching mapped wording is made in `copilot/map` too, and an entry matching nothing is refused.
- Claude Code has no handoffs: the user-invocable agents run as `claude --agent <Name>`, and a body names the next session where the Copilot copy names a handoff.
- `handoffs` link user-invocable agents along meaningful transitions only and are all manual — never set `send: true`: Autopilot auto-fires the first `send` handoff after every response and can loop agents. Prompts are inserted verbatim (no `${…}` substitution) into the same session, so they name only what is handed over plus facts the target cannot see (e.g. ledger paths); the target agent's body supplies the method (`copilot/<name>.yml`).
- Challenger and Reviewer share one verbatim `## Constraints` block and the quoted fit question; Orchestrator and that block share the Executor-dispatch sentence; Scout, Executor, and Coder share the auto-approval bullet; Planner, Orchestrator, and Challenger share the Language rule, the Parallel dispatch rule, and the Memory rule — there is no include mechanism, so edit every copy together.

## Checks

- `make check` — Prettier format check + markdownlint + shellcheck + bats, the full suite.
- `make format-check` — Prettier check on Markdown.
- `make lint` — markdownlint on Markdown + `shellcheck -s sh` on `scripts/*.sh` and `tests/mock/*` + `shellcheck -s bash` on `tests/helpers.bash`; `.bats` files are not shellchecked.
- `make test` — bats-core on `tests/*.bats`.
- `make format` — Prettier rewrites Markdown.
- These targets, or the commands they run on specific files, may run locally without asking.
- CI (`.github/workflows/ci.yml`) runs `make check` on `ubuntu-latest` and `macos-latest` for pushes to `master` and all PRs.

## Conventions

- Agents orchestrate, Executor executes: a body holds its flow plus only its role's knowledge; the git/gh workflow lives only in Executor's Rules, each fixed multi-command flow is a script in `scripts/`, and the dispatchers — Orchestrator, Reviewer, and Challenger — name a git/gh step by its intent alone, the exceptions being the Coder's own fixed commands: the worktree scripts that cut and release its worktree, `git add`/`git commit`, `git restore`/`rm`, and the `git worktree remove` undoing an accidental attach (its Git writes constraint, Worktree and Release steps); no body restates the harness base prompt.
- Agent bodies open with one sentence in normal case, `You are the <role>: <mission>.` — no shouted words.
- Agent body sections are H2 only, one per name, in this order and only when needed: Input, Constraints, Approach (a subagent's checklist) or Workflow (the Orchestrator's and Planner's phase loop), Rules, Output Format.
- List items are fragments or single sentences without a terminal period — split an item rather than write two sentences in it; only Workflow phase items are paragraphs with a bold `**Phase**:` label and full punctuation, every other label is plain `Label:`.
- Emphasis: `_Agent_` italics for agent names, bold only for Workflow phase names — their labels and references back to them — and a body's key-fact line (`**Ledger**`, `**Current plan**`), backticks for paths and commands, a Claude Code tool by its bare name (`copilot/map` turns it into `#tool:`); a list's lead-in sentence ends with a colon.
- Descriptions: at most 35 words, shorter preferred; one outcome clause (what it does, not its steps), then `Use when:` with up to three comma- or semicolon-separated triggers specific to the task; no model names; a dispatch-only agent's description names no dispatcher or dispatchee, a user-invocable agent's may name the agents whose handoffs feed it; the limits count the text before `Brief:` (`agents/*.md` frontmatter).
- Shell: auto-approvable and self-contained; a fixed flow is one script call, approvable whole; no `export …;` preamble or `VAR=… cmd` prefix and no zsh-only syntax; guards are flags, not environment; `gh` output piped; watchers included in the foreground rather than redirected (Executor's Constraints and Rules, Coder's Terminal constraint, the auto-approval bullet shared by Scout, Executor, and Coder).
- Testing: the full suite runs on CI as the merge gate and local runs stay targeted — the baseline is the start commit's CI result, taken once per task (Orchestrator's Intake), else one local run, and a local full run comes only before a landing to no PR or when CI is unreachable (Executor's CI and Landing rules, `scripts/ci-wait.sh`).
- Execution: only Scout (side-effect-free reads), Executor (git/gh flows and dispatched checks), and Coder (its own worktree's tests, builds, checks, and fixed git steps) run terminal commands, each listing `Bash` in `tools`, its Copilot copy naming the `execute/<tool>` entries instead of the `execute` set; Orchestrator, Reviewer, and Challenger dispatch Executor by its `argument-hint`, one dispatch per step; destructive commands only when named (Executor's Constraints and Rules, Coder's Constraints, the shared Executor-dispatch sentence).
- Implementation: the Orchestrator copies each module entry into the ledger as its stage's contract and runs the stage by one Coder writing tests and implementation together (its Intake and Execute); a Coder creates and releases its own worktree, so its stage exists only as the branch it reports (Coder's Worktree and Release steps); Executor lands a wave's branches in dependency order and cleans up by branch, combining only by rebase and fast-forward, never a merge commit (its Landing rule, `scripts/worktree-*.sh`).
- Review: the review requirement is the user's choice among review gates as the Orchestrator schedules them (the default), one review gate before landing only, or none; Reviewer runs at the gates only and Challenger only when the user asks or a gate fails three Reviewer rounds (Orchestrator's Intake and Verify, Planner's Alignment).
- Design: the Planner designs from the whole by criteria that live only in its Modules rule; the Orchestrator decomposes the design; Coder implements the contract, reporting rather than writing a patch or restructuring the plan did not foresee; Reviewer and Challenger ask the fit question against the plan's decisions and criteria (their Approach).
- State: the plan file and the task ledger live in the main checkout's `.git/agents/` — untracked and shared by every worktree — and are the only files Planner and Orchestrator write; the Copilot copies keep them in `/memories/` (Planner's **Current plan**, Orchestrator's **Ledger**, `copilot/map`).
- Planning: the Planner's Outline, approved by the user, is the only plan format, each module entry carrying its acceptance criteria and becoming the ledger's stage contract verbatim (Planner's Output Format, Orchestrator's Intake).
- Dispatch interface across agents: the description's `Brief:` is the single home of what a dispatch must carry; `## Input` restates it with semantics and adds nothing; a dispatcher's brief adds only what the `Brief:` cannot know and never describes the target's method; no body describes another agent's mechanics (Orchestrator's `Stage dispatches:` rule).
- Dispatch policy across agents: subagent dispatches needing none of one another's results or side effects form one batch issued in one tool-call block; a dispatch issued after another has returned runs alone; each body names its batches (the shared `Parallel dispatch:` rule).
- Dispatch models across agents: a dispatch runs on the model its dispatcher names via the Agent tool's `model` parameter, else on the target's `model`, and only the Orchestrator, for every Coder dispatch by the stage's difficulty, and Challenger, for its three Reviewer dispatches, name one; the aliases need no change on a model version upgrade, while the Copilot names in `copilot/map` change together with the `copilot/*.yml` `model` lists (Orchestrator's `Coder model:` rule, Challenger's Cross-examination step).
- Language: Planner, Orchestrator, and Challenger share one `Language:` rule — replies and questions (options included) in the user's language, read from the user's own messages and never from a dispatch brief, naming anything referred to (stages, modules, waves, review gates, decisions, findings) by what it is, never by the plan's, the ledger's, or their own numbers or labels; nothing else is bound to it; commits, issues, and PR text keep the project's language (Coder's Commit step, Executor's PR and Issue rules).
- Memory: Planner, Orchestrator, and Challenger share one `Memory:` rule — a reusable rule the user states is offered back as one line of at most about 300 characters, never written by the agent; the Copilot copy's rule writes it to user memory instead (their Rules, `copilot/map`).
- Reports: Scout, Executor, Coder, and Reviewer cap a report at 5000 characters unless the brief sets another bound (their Output Formats).
